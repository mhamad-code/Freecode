## F1 details

- **Lite mode** (`src/engine/providers/lite.ts`, preference in `src/lib/liteMode.ts`): `auto` / `on` / `off`, with `auto` enabling it for a keyless service that publishes ≤30 req/min or ≤60 req/h, or that just returned 429. Lite sends one short system prompt, no tools, no reasoning effort, at most 1024 output tokens and the last 8 messages (images and orphan tool results dropped). The chat shows a `lite.banner` notice, and the Providers tab carries the control plus the shared free-service consent copy.
- **Per-provider serial queue** (`src/engine/providers/queue.ts`): `ProviderRegistry.chat` and `refreshCatalog` run one request at a time per provider id, so two turns cannot race into the free per-IP limit; different providers still run in parallel. A rejected task does not poison the queue.
- **Retry-After backoff** (`src/engine/providers/backoff.ts`): retriable failures (rate/server/network/timeout) get one extra attempt by default. The provider's Retry-After wins (seconds, `retry after N`, or an HTTP date), capped at 5 s of delay and 10 s of wait; a longer Retry-After is surfaced to the UI instead of hanging, and nothing is retried once the first delta exists.
- **Classification fix**: `parseRetryAfter` now also accepts an HTTP date.
- **Provider test fix**: `testProviderConnection` now passes its injected `fetchImpl` into the registry (`registryFor(list, { fetchImpl })`), so provider tests no longer silently use the real network.
- **OVH built-in fixed**: `Bearer anonymous` is rejected with 403 now (catalog and chat). The provider is keyless again (`auth.type: 'none'`), matches the catalog's 200 response, and stays limited to ~2 req/min.
- **10 real keyless requests** (from this VM, `Origin: https://freecode-2j3.pages.dev`):
  - LLM7 catalog **200**, CORS `*`, 89 models, prices in USD/1M tokens; `gpt-oss:20b` short chat **200 + SSE**, and an agent-sized payload (long system prompt + tool schema) also **200 + SSE** — no 429 today.
  - Kilo catalog **200** (470 models, e.g. `kilo-auto/free`), chat **200 + SSE** (`nvidia/nemotron-3.5-super-vl:free`), but **no `Access-Control-Allow-Origin`** on either response, so the browser still blocks it.
  - OVH: catalog with `Bearer anonymous` **403**; plain catalog **200** (33 zero-priced models); plain chat `clef-flash` **404 model_not_found**; plain chat `gpt-oss-20b` **429 API rate limit exceeded** (no Retry-After header).
- Note: LLM7 now declares paid pricing for every catalog entry, so no LLM7 model is marked `free` by the catalog; keyless use still works but the models sit under "Show all" unless one is selected or tested.
- **LLM7 charges the requested `max_tokens` against its anonymous allowance.** Same minute, same browser: `max_tokens: 1024` → 429, `max_tokens: 256`/`64` → 200. A Lite turn therefore retries once with `LITE_REDUCED_MAX_TOKENS` (256) on a rate error and shows `lite.reduced`. After the day's probing the IP's allowance was fully spent (`retry in 39345 seconds`), which is why no full reply was rendered.
- Lite turns now also keep a per-attempt "did output start?" flag, so the reduced retry can never replay a stream that already produced text.

## F2 details

- **Editor** (`src/components/CodeEditor.tsx`, loaded with `lazy()` from `ToolPane`): CodeMirror 6 with line numbers, active-line highlight, history, bracket matching, `indentWithTab`, a theme built only from CSS tokens (`--text`, `--accent`, `--success`, `--warning`, `--danger`, `--faint`, `--muted`) and a `HighlightStyle` over `@lezer/highlight` tags. Language is chosen from the file extension (TS/TSX/JS/JSX, JSON, CSS, HTML, Markdown); anything else is plain text. The view is recreated only when the open file changes; external value changes are dispatched as a full-document transaction.
- **Compare** (`DiffView` in the same chunk): `@codemirror/merge` `MergeView` of the saved contents (A) against the working buffer (B), read-only, with change highlighting. Reached with the "Compare" button in the editor header.
- **Terminal** (`src/components/XTerm.tsx`, lazy): a real xterm.js instance with `@xterm/addon-fit`, font and colours read from the live CSS variables (and repainted when the theme changes). Typed commands are echoed and answered with `terminal.noRuntime`; there is still no shell, so nothing executes. This replaces the fake `<input>` line and the boot-animation `connected` state.
- **Reachable editor**: the Files panel's "New file" button now really creates an empty file (`notes.md`, then `notes-2.md`, …) through the new `createFile` store action and opens it, instead of showing a toast. Without it the editor had no way in on a fresh profile.
- **Lazy guard** (`src/lib/__tests__/lazyHeavy.test.ts`): fails if `ToolPane` or any other module imports `CodeEditor`/`XTerm` statically, so the 278 kB of extra JS never lands in the entry chunk.

## F4 details

- **Boot** (`src/runtime/webcontainer.ts`): `runtimeSupport()` reports `full` / `no-isolation` / `no-sab`; `bootRuntime()` checks cross-origin isolation first, then `await import('@webcontainer/api')` and `WebContainer.boot({ coep: 'credentialless', workdirName: 'project' })`. The package is never imported statically, so the app entry stays free of the runtime client.
- **Workspace** (`src/runtime/workspace.ts`): the store's flat `path → contents` map becomes a `FileSystemTree` and is mounted into the container when the runtime starts; `syncFile()` writes editor saves through to the container (and is a no-op before boot).
- **Terminal** (`src/runtime/terminal.ts` + `src/components/XTerm.tsx`): with isolation, xterm is wired to `container.spawn('jsh', { terminal: { cols, rows } })` — input goes to the process, `output` is piped back, resize is forwarded. Without isolation the old honest echo returns `terminal.noRuntime`.
- **Preview** (`src/runtime/preview.ts` + `previewServer.ts`): writes a CommonJS static server into `.freecode/preview-server.cjs`, runs it with `node`, waits for the `server-ready` event for port 5173 and shows the returned URL in an iframe. It serves existing files with a small MIME map, falls back to `index.html`, and otherwise renders a project listing — it never invents an app.
- **State** (`src/runtime/state.ts`): one external store (`useSyncExternalStore`) with boot phase, mounted file count, preview phase/URL/error, shared by the preview panel and the terminal.
- **Fallbacks**: `/settings` runtime status and the workspace `RuntimeBanner` still describe the limited mode; the preview panel explains why it cannot start instead of showing mock content.

## F5 details

- **One project FS for the agent and the editor** (`src/lib/projectBridge.ts`): `projectFsFor(sessionId)` opens `createProjectFs('local', …)` once per session (OPFS, IndexedDB fallback) and caches the promise, dropping it if the open fails. `mountProjectFiles()` copies the store's files in, skipping paths whose bytes already match, and `readProjectFile()` is the read side.
- **The agent writes where the user looks** (`src/lib/agentClient.local.ts` + `src/store.ts`): `runLiveTurn` mounts `files` before the first model call, and after each `write_file`/`edit_file` it reads the file back and calls `onFileWrite`, which becomes `writeProjectFile` in the store: tree node (created when new, `A`/`M` otherwise), `fileContents`, and `syncFile` into the running container.
- **Checkpoints are real snapshots** (`src/lib/checkpoints.ts`): every live or demo turn captures the project's file contents before the first model call (label from i18n), keeps at most 20 per session, and the turn stores the id plus the file count. `diffContents()` compares a snapshot with the project, and `treeFromContents()` rebuilds the file tree for a restore.
- **Restore** (`store.restoreCheckpoint`): three scopes — “code and conversation”, “code only”, “conversation only”. Code restore replaces `fileContents`/`files` with the snapshot, writes each file to the project FS, syncs to the container, and removes files created after the checkpoint. Conversation restore drops the turn and the user message that started it.
- **Recovery card** (`RecoveryCard` in `Chat.tsx`): when a turn fails and the project differs from its checkpoint, the turn carries `recovery.changed`, the card names the count and offers “Restore files” or “Keep changes” (which clears the flag).
- **Steering queue** (`Session.queued` + `enqueue`/`removeQueued` + `drainQueue`): typing while a turn runs queues the text in the session (not in a component), the composer shows a removable chip, and the next message is sent as soon as the turn finishes or the user comes back to that chat.
- **Fixed**: `OpfsFS.list()`/`walk()` threw `Absolute paths are not allowed` for top-level entries.

## F6 details

- **The profile survives a reload** (`src/lib/persist.ts`): one profile snapshot (`meta/profile` in `freecode:local`) holds the sessions, the active session id, the file tree, the file contents and every checkpoint. `main.tsx` awaits `hydrateStore()` before the first render, so the same chats and files come back instead of an empty workspace; a turn that was running when the tab died is loaded as a stopped turn, not as a spinner that never ends. `startPersistence()` subscribes to the store and writes after 800 ms of quiet plus once on `pagehide`. Storage failures (blocked IndexedDB, quota) are swallowed: the app keeps working, it just stops surviving reloads.
- **Checkpoints are part of the profile**: `exportCheckpoints()`/`restoreCheckpoints()` move the in-memory history in and out of the snapshot, and the `seq` counter is restored so ordering stays deterministic.
- **`.freecode` archive** (`src/lib/archive.ts`): a ZIP built with `fflate` holding `manifest.json` (`format`, `version`, `createdAt`, `activeSessionId`, `settings`, `sessions`, `checkpoints`) and `files/<path>` for every project file. Paths are re-checked with `safePath`, so `../` or absolute entries are dropped on export and ignored on import; only the `files/` prefix is read back; a newer `version` or another format is refused with a clear message. Settings → General exports the archive and imports it through `applySnapshot`, which also rebuilds the tree from the contents; the old JSON backup is still accepted.
- **PWA shell** (`public/manifest.webmanifest`, `public/sw.js`, `index.html`, `main.tsx`): the manifest declares the name, colours and the existing 180 px icons; `sw.js` precaches the shell, serves navigations network-first (so a new deploy wins) with the cached `index.html` as fallback, and caches same-origin assets on first use. It is registered only in a production build.
- **Checkpoint restore now clears the agent's view too** (`projectBridge.removeProjectFiles`): restoring code deletes the post-checkpoint files from the session's `ProjectFS` (and prunes folders that became empty), not only from the store and the container, so the next agent turn cannot read a file the UI already dropped. This exposed a real `MemoryFS.remove()` defect — it deleted descendants but never the file at the given path — which is fixed, and the IndexedDB fallback (which delegates to `MemoryFS`) now persists the deletion.

## F7 details

- **Real client, no SDK**: `src/lib/github.ts` talks to `https://api.github.com` with an injected `fetch` (so tests never hit the network). It covers `/user`, `/user/repos`, branches, the branch head commit/tree, recursive trees, and a real commit: create one blob per file → create a tree with `base_tree` → create a commit with the branch head as parent → `PATCH` the branch ref (`force:false`). A failure leaves the branch untouched.
- **Real diff without downloads**: `blobSha` hashes `"blob <len>\0" + bytes` with SHA-1 (checked against Git's known ids for `""` and `"hello\n"`), and `diffAgainstRemote` compares those ids with the branch tree; `.freecode/` is excluded.
- **Token handling**: the PAT is verified against GitHub before anything is stored, kept in `sessionStorage` (`src/lib/githubAuth.ts`) so it disappears with the tab, and is never part of the profile snapshot, the `.freecode` archive or IndexedDB. The repo target (`owner/repo/branch`) is not secret and lives in `localStorage`.
- **Connect screen**: GitHub no longer simulates a connection. Success shows the real login name; failure shows GitHub's message and HTTP status. The false “Secured by Composio” line is gone, and OAuth services now say plainly that the screen records the connection locally and does not contact the provider.
- **Changes panel**: a GitHub bar shows either the honest local-only state + Connect button, or a repository picker, a real branch list from the API, a commit message and Push. On Push it reports the real commit SHA with a “View commit” action. The fake `push`/`pull` store actions (which toasted “Pushed to origin/main”) were deleted, Pull is disabled with a reason, and “Commit & push” points to the bar.
